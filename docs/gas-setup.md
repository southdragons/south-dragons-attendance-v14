# South Dragons_J.B.C. 出欠管理 — 初期設定

対象は、今回作成した **South Dragons_J.B.C. 出欠管理** スプレッドシートです。
まず「1」「2」まで行えば、必要な4シートを用意できます。
スプレッドシート自体は非公開のままで構いません。

## 1. Apps Scriptを開いてコードを貼る

1. スプレッドシートを開く。
2. 上部メニューの **拡張機能 → Apps Script** を選ぶ。
3. Apps Scriptのプロジェクト名を `South Dragons 出欠API` などにする。
4. 最初に表示される `コード.gs` の `myFunction` を含む内容を、プロジェクト内の **gas/Code.gs の全文**で置き換える。
5. 保存する。

`Code.gs` のスプレッドシートIDなどを書き換える必要はありません。
スプレッドシートからApps Scriptを開いたことで、対象を自動で取得できます。
別の既存コードがあるプロジェクトは上書きしないでください。

## 2. 4シートを自動作成する

1. エディター上部の実行する関数から **setupSouthDragons** を選ぶ。
2. **実行** を押す。
3. 初回の権限確認では、使用しているGoogleアカウントを選択して、コードと要求されたスプレッドシート権限を確認のうえ承認する。
4. 実行完了後、元のスプレッドシートへ戻る。

次の4シートが追加されていれば成功です。

- `players` — 選手
- `events` — 予定
- `attendance` — 出欠
- `settings` — チーム設定

最初からあった「シート1」はそのまま残ります。削除する必要はありません。
サンプルの選手や出欠は実データへ移しません。
関数をもう一度実行しても登録済みのデータや接続キーは消えません。
既存シートの1行目が想定と異なる場合は、上書きせずエラーで止まります。

GASのV8ランタイムが必要です（新規プロジェクトの標準）。マニフェストを管理する場合は `gas/appsscript.json` を使用できます。貼り付けだけの導入では変更不要です。

## 3. GASをWebアプリとしてデプロイする

1. Apps Script右上の **デプロイ → 新しいデプロイ**。
2. 種類を **ウェブアプリ** にする。
3. **次のユーザーとして実行：自分**。
4. **アクセスできるユーザー：全員**。
5. デプロイし、表示された **ウェブアプリURL** を控える。

URLは `https://script.google.com/macros/s/…/exec` の形式です。
スプレッドシートのURLや、テスト用の `/dev` URLとは異なります。
組織アカウントのポリシーで「全員」が選べない場合は、その時点で状況を知らせてください。

この公開設定はGASの入口に対するもので、スプレッドシートの共有設定を公開にはしません。
GASは接続キーを検証し、認証できないリクエストにはデータを返しません。
コードを変更した際は、**デプロイを管理 → 編集 → 新しいバージョン**を選び、同じURLを更新します。

## 4. Nuxtに接続情報を設定する

Apps Script左側の歯車 **プロジェクトの設定 → スクリプト プロパティ** を開きます。
初期設定で次の値が自動生成されています。

| プロパティ | 用途 |
| --- | --- |
| `SPREADSHEET_ID` | 保存先。自動取得するため変更不要 |
| `API_KEY` | NuxtサーバーとGAS間の接続用秘密キー |
| `ADMIN_SETUP_CODE` | 初回だけ使う管理パスワード設定コード |

SouthDragonsフォルダに `.env.example` をコピーして `.env` を作り、以下を入力します。

```dotenv
NUXT_GAS_WEB_APP_URL=https://script.google.com/macros/s/あなたのデプロイID/exec
NUXT_GAS_API_KEY=スクリプトプロパティのAPI_KEYの値
```

`.env` はGit管理対象外です。**API_KEY、初期設定コード、管理パスワードはチャットへ貼り付けなくて構いません。**
`NUXT_PUBLIC_` の付いた変数名に変更しないでください。
変更後、開発サーバーを再起動します。

```sh
npm run dev
```

画面が「デモモード」から「チーム共有」に変わり、登録前の空の一覧になります。
どちらか一方だけ設定した場合もGASモードとなり、設定不足のエラーを表示します。
接続に失敗してもデモデータへ戻ったり、デモをスプレッドシートへ送ったりはしません。

## 5. 最初の管理パスワードを設定する

1. アプリの **管理** を開く。
2. `ADMIN_SETUP_CODE` を「初期設定コード」に入力。
3. 運営者で共有する管理パスワードを12文字以上で入力し、確認欄にも入力。
4. **パスワードを設定する** を押す。

成功すると管理画面に入り、初期設定コードはGASから削除されます。
次回からは共通管理パスワードでログインします。
管理パスワードを変更すると、ログイン中の運営者も再ログインが必要になります。
認証に10回失敗すると、チーム共通で最長15分間ログイン試行が制限されます。

## 6. 接続確認

1. 管理画面から実際の予定を1件登録する。
2. 出欠確認画面で選手名を登録する。
3. 予定の出欠を入力し、スプレッドシートの `attendance` に行ができることを確認する。
4. 同じWi-Fiに接続した別端末で開き、「更新」を押して同じ回答が見えることを確認する。
5. 管理画面で非表示・再表示、退団・復帰も確認する。

別端末には「自分の選手」の設定は引き継がれません。既存の名前を登録して「この選手を使用する」で選択できます。
新しい回答を取得するには画面の「更新」またはブラウザ再読み込みを使います。
複数端末が同じ出欠を同時変更した場合は、最後に保存された回答が採用されます。

## 公開環境について

この接続版はNuxtのサーバーAPIを使用するため、**Node.jsサーバーでの運用が必要**です。
静的ファイルだけのホスティングには対応していません。
本番はHTTPSで公開し、ホスティング先の環境変数にも上記2項目を設定します。

```sh
npm run build
node .output/server/index.mjs
```

本番で `.env` は自動読み込みされないため、必ずホスティング先の環境変数を使用してください。
一般の保護者はアカウント登録不要です。共通アプリURLを知る利用者が選手登録・出欠変更を行う方式なので、チーム内でURLを共有してください。
