# GAS接続の開発メモ

利用者向けの操作手順は [gas-setup.md](gas-setup.md) を参照。

## 構成

保護者のブラウザ → Nuxt `/api/team` → GAS `doPost` → 非公開スプレッドシート。

- `gas/Code.gs` はデプロイ用の実コード。`setupSouthDragons` で4シートと接続キーを作る。
- `server/api/team-mode.get.ts` は接続環境変数の有無だけを返す。秘密値は返さない。
- `server/api/team.post.ts` は操作をホワイトリスト化し、接続キーと管理セッションをサーバー側で添付。
- `server/utils/gas.ts` はGASへのJSON POST、リダイレクト追従、タイムアウトとエラー変換。
- `app/composables/useTeam.ts` はdemo/GASを切り替え、成功レスポンスを受け取ってから共有データを更新。

## 認証

初期設定時、GASが作成する `ADMIN_SETUP_CODE` を初回だけ使用する。
NuxtのNode.js標準cryptoでscrypt（N=32768, r=8, p=3、ランダムsalt32バイト、出力32バイト）を計算する。
GASへは平文パスワードを送らず、接続キーで認証済みのNuxtから導出値を送る。
GASは保存された導出値と比較してログイン可否を判定する。
`settings.admin_password_hash` の単一セルへalgorithm/salt/hash/versionのJSONを保存し、パスワード変更時に同時更新する。
導出値はログイン資格情報と同等なので、ブラウザやログに出さない。

管理セッションは有効期限8時間。GASのスクリプトプロパティにトークンのSHA-256をキーとして保存。
ブラウザにはHttpOnly/SameSite=StrictのCookieのみ。HTTPS時はSecureを付ける。
GASは管理処理ごとにセッションとパスワード世代を検証する。変更・ログアウトで無効化。
共通パスワードのため、GAS上の試行制限も共通（15分間に10回）。
NuxtはJSONと専用リクエストヘッダーを要求し、別オリジンからの変更要求を拒否する。

## データ整合性

全GASリクエストをスクリプトロックで直列化する。登録前に名前を再確認し、出欠はevent_id/player_idでupsert。
予定の新規登録にはクライアント生成UUIDを使い、同じフォームからの再試行で二重登録しない。
未回答への変更だけは該当の出欠行を除去。選手・予定は物理削除しない。
イベントの非表示・選手の退団は明示的なboolean指定なので、同じ要求を再送しても反転しない。
過去日の出欠と退団者・非表示予定への出欠変更はGASで拒否する。
日付はAsia/TokyoのYYYY-MM-DD、時刻はHH:mm。セルには文字列書式を指定。
ユーザー入力が数式として解釈されないよう、危険な開始文字にはアポストロフィを前置する。

読み取りはgetDisplayValuesを使用。セルの文字列処理・権限・ネットワークは実GAS上でも接続確認が必要。
サーバーや通信のエラー後は保存済みの可能性もあるため、自動リトライせず再読み込みで結果を確認する。
Google Sheetsには複数API呼び出しをまとめたトランザクションはない。保存後のsnapshot取得が失敗しても保存自体は完了している場合がある。
同一回答の競合は最終保存優先。端末ごとのローカルデータ全体を上書き送信しない。

## 公開・運用

Node.jsサーバーを使う。静的generateは接続版では使えない。
公開環境の環境変数に `NUXT_GAS_WEB_APP_URL` と `NUXT_GAS_API_KEY` を設定。
GASのアクセス範囲「全員」は接続エンドポイントのみであり、スプレッドシートは非公開を維持する。
Nuxt側の公開操作は共通URLを知る利用者向け。役員はパスワードを、Googleファイルの管理権限はチームのアカウントで引き継ぐ。

次の段階は実デプロイの接続確認とLINE連携。LINEはトークンをGAS側に保持し、翌日の有効なイベントが0件なら送信しない方針。
