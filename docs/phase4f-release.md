- **画面より先にSQLを戻さない。** 新しい画面＋古いSQLの間は、「次へ」（登録前の確認）で選手がすぐ登録されてしまう。
- ロールバックSQLを実行したあとで閲覧制限を有効にすると、前の動作（出欠を入力できる端末すべてを追加）に戻る。閲覧制限を有効にするのは、4-F2 を再び反映してからにする。
- `players.verified_at` の列はロールバック後も残る（使われない）。再反映しても、反映時点の選手を確認済みにする処理は1回目にしか動かない。

## 5. 閲覧制限が無効の間に残るリスク
- 公開URLを知っている人は、チームコードなしで、選手名・予定・出欠を見られる（今と同じ）。名前での検索や「登録済み選手の端末を追加」の一覧は、この状態では新しい情報を漏らさない。
- 架空の選手を登録すると、今までどおり一覧に表示される（管理者が「退団」にする）。4-F2 により、その端末は閲覧制限を有効にしても自動では閲覧できない。

## 6. この反映で変わらないこと
- 出欠の入力（`save_own_attendance`）、予定、選手の名前の変更・退団、端末の権限の解除、チームコードの入力。
- 端末共有の申請と、そのLINE通知の本文・送信先・回数。
- 欠席通知（`attendance-reminder`）。
